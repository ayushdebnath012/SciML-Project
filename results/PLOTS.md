# Where every plot lives

## Paper figures — `sci_ml/figures/`

Generated by `python sci_ml/make_figures.py` from the result files. Three, all
in the built PDF:

| file | what | where in the paper |
|---|---|---|
| `fig_fields.pdf` | the solution itself: FD reference vs recipe vs ablated vs worst run, all three materials | Figure 3, body |
| `fig_causal.pdf` | causal weight per time slab over training — a stalled frontier beside the one that completes | Figure 2, body |
| `fig_cost_accuracy.pdf` | accuracy against wall-clock for both families | Figure 1, appendix |

`fig_fields.pdf` is drawn from `results/fields.npz`, exported off the training
box by `wave/server/export_fields.py`. That script runs the same prediction path
the runner uses to compute the reported error, so a field in the figure and the
number in `l2_errors.json` cannot disagree — it prints both side by side to
prove it.

## Per-run diagnostics — 509 PNGs under `results/`

Every run writes its own plots. These are the runner's own 300-dpi output, not
paper figures, and they are for inspecting a run:

| file | one per | what |
|---|---|---|
| `solution_comparison.png` | 143 runs | 3-panel FD reference / prediction / absolute residual |
| `loss_curve.png` | 122 runs | total loss against Adam iteration, log scale |
| `gradnorm_weights.png` | 122 runs | `w_pde`, `w_bc`, `w_ic` against iteration |
| `causal_wmin.png` | 122 runs | the `w_min` diagnostic against iteration |

Laid out as `results/<tree>/<Material>/<RunName>/<plot>.png`:

- `results/pinn/` — the main sweep, 99 runs. The 57 causal runs here are the
  **corrected** versions (see below).
- `results/pinn_ablation/` — the weighting ablation, 44 runs.
- `results/pinn_original/` — the same 99 sweep runs **before** the continuation
  fix, kept so the correction can be checked rather than taken on trust.

The 21 runs with no `loss_curve.png` / `gradnorm_weights.png` / `causal_wmin.png`
are the L-BFGS-only arm: no Adam phase, so no Adam-indexed history to plot.

## Refetching

```bash
RPASS='...' python wave/server/fetch_results.py --include-plots
```

Without `--include-plots` only the JSONs come across, which is the fast path for
regenerating tables. The corrected causal tree is layered over the original
deliberately — see the comment on `REMOTE_LOCAL` in that script.
